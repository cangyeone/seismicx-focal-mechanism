# SeismicX Focal Mechanism

[English](README.md) · [简体中文](README.zh-CN.md) · [Validation](docs/VALIDATION.md)

**DNN travel times, gradient-derived takeoff angles, first-motion classification, and joint CAP/first-motion double-couple inversion.**

This private research repository contains the application source, trained networks, fixed velocity-model definitions, and a runnable synthetic example. CSNDATA raw records, training-label banks, temporary Green caches, and machine logs are not tracked. SeismicX GRTM is an external dependency: its solver implementation is not redistributed here.

## 1. What the program does

| Mode | Inputs | Outputs |
|---|---|---|
| `polarity` | Geometry and raw Z windows, continuous raw Z, manual U/D, or U probabilities | Equivalent nodal planes, normalized moment tensor, first-motion mismatch counts, station geometry and mechanism plot |
| `joint` | The same first-motion inputs plus response-corrected displacement waveforms | CAP + first-motion solution, moment tensor in N m, Mw, selected depth, group time shifts, waveform fits and mechanism plot |
| `arrivals` | Source depth, epicentral distance, phase and optional surface-wave periods | Neural travel time, input gradient, takeoff angle, validity, and Rayleigh/Love group arrivals |

**Normal inference does not import ObsPy or TauP.** Offline body-wave training uses TauP reference labels. Surface-wave labels come from the GRTM Rayleigh/Love eigenmode solver. Complete synthetic waveforms are generated by physical GRTM, not by the travel-time DNN.

The solver fits a double couple. A nodal-plane pair is equivalent; a different reported strike/dip/rake can represent the same moment tensor. Full unrestricted moment-tensor decomposition is not implemented.

## 2. Installation

### Tested environment and model files

The recorded validation used Linux/WSL, Python 3.13, PyTorch 2.8.0 + CUDA 12.8, SeismicX GRTM **0.6.0.dev12**, and two RTX 5090 GPUs. Neural inference and first-motion fitting also have CPU paths. This joint application does not select an MPS backend.

GRTM's dev12 native wheels are available for Linux x86_64 / CPython 3.13 / glibc >=2.31 and macOS arm64 / CPython 3.12. The Linux CUDA binary targets SM120. Availability of a wheel does not mean this application was validated on every platform.

1. Clone this private repository using an account with access:

```bash
gh repo clone cangyeone/seismicx-focal-mechanism
cd seismicx-focal-mechanism
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
```

2. Install PyTorch for your device, then the small Python dependencies. The recorded CUDA configuration can be reproduced with:

```bash
python -m pip install torch==2.8.0 --index-url https://download.pytorch.org/whl/cu128
python -m pip install numpy scipy matplotlib
```

For CPU-only use, install a matching CPU PyTorch distribution instead. On Apple Silicon use Python 3.12 with the matching native GRTM wheel and `--device cpu`.

## 3. Quick start

All commands below run from the checkout with its Python environment activated. Use `cuda:1` for the second GPU or `cpu` for CPU execution.

### Query travel times and takeoff angles

```bash
seismic-joint arrivals --earth-model iasp91 --depth 10 \
  --distance 30 100 300 \
  --phases P_first S_first Pg_regional Pn Sg_regional Sn pP sP PP SS \
  --period 10 20 40 --device cuda:0
```

Depth and epicentral arc distance are in **km**, time in **s**, and angles in **degrees**. JSON represents unavailable numeric values as `null`; inspect validity masks before using angles.

### First-motion-only example

```bash
seismic-joint invert examples/polarity/event.json \
  --mode polarity --device cuda:0 --output results/demo_polarity
```

This example contains synthetic geometry and continuous U probabilities, so it needs no waveform files. Sparse first motions may admit several mechanisms; use it to exercise the interface, not to estimate real-event accuracy.

### Joint CAP + first-motion example

```bash
seismic-joint invert examples/synthetic/event.json \
  --mode joint --device cuda:0 --output results/demo_joint
```

The supplied response-corrected synthetic displacement records use a known GRTM source, 0.5% global-RMS Gaussian noise, and depths `[8, 10, 12]` km. First-motion probabilities were generated from the known source and neural rays; they are **not CNN classifications of these low-rate synthetic traces**. The first call computes physical Green banks; repeated identical configurations reuse `green_cache/`.

![Synthetic five-segment CAP fit](docs/figures/waveform_fit.png)

This is a matched-model synthetic recovery experiment, not a real earthquake accuracy claim. Numerical results are in [the validation report](docs/VALIDATION.md).

## 4. Prepare your event

Paths to input waveform files are resolved relative to the event JSON. Station order in the waveform array must match the `stations` list.

```json
{
  "event": {"id": "my_event", "depth_km": 10.0},
  "earth_model": "iasp91",
  "stations": [
    {"id": "XX.AAA", "distance_km": 80.0, "azimuth_deg": 35.0,
     "raw_z_file": "AAA_P_Z.npy", "phase": "P_first"},
    {"id": "XX.BBB", "distance_km": 120.0, "azimuth_deg": 160.0,
     "polarity": "D", "phase": "P_first"}
  ],
  "waveform": {
    "file": "observations.npz", "quantity": "displacement_m",
    "coordinates": "NEZ", "dt_s": 0.25, "t0_s": 0.0
  },
  "source_duration_s": 1.0,
  "synthetic_samples": 1024,
  "depth_grid_km": [8.0, 10.0, 12.0],
  "cap": {"starts": 64, "steps": 1000, "polarity_weight": 0.2}
}
```

Two stations above illustrate the schema, not sufficient coverage for a unique mechanism. For first-motion-only mode omit `waveform`, `source_duration_s`, `synthetic_samples`, and `depth_grid_km`.

### Geometry and first-motion inputs

| Field | Meaning |
|---|---|
| `event.depth_km` | Reference source depth; also the fixed data-window depth across a joint depth search |
| `earth_model` | `iasp91` (default), `ak135`, or `prem` |
| `stations[].id` | Unique station ID |
| `distance_km`, `azimuth_deg` | Epicentral arc distance; source-to-station azimuth clockwise from north |
| `phase` | Direct-P ray family used by the polarity observation; default `P_first` |
| `raw_z_file` | `.npy` containing one raw 1024-point, 100 Hz, Z-up window; normalization is internal |
| `raw_z_continuous_file` | `.npy` containing a full raw 100 Hz Z-up trace; give `raw_z_t0_s` |
| `raw_z_t0_s` | Continuous Z record start time, seconds relative to the earthquake origin |
| `p_time_s` | Optional observed P pick, seconds since origin; otherwise a DNN arrival centers the crop |
| `raw_z_dt_s` | Continuous Z sampling interval, default/required `0.01` s |
| `polarity` | Manual `U` or `D` |
| `probability_u` | Existing U probability in `[0,1]` |

Choose **one** polarity input type for each station. The reader prioritizes `probability_u`, then `polarity`, then `raw_z_file`, then continuous Z. A station without first-motion information can still contribute CAP waveforms.

For a pre-cut raw window, P should lie at sample index **256–767** (zero based). The continuous-trace path uses linear interpolation with nominal P at index 512. The CNN was trained with randomized P positions and paired sign reversal. It accepts raw amplitude, demeans in float64 and divides by sample standard deviation before FP32 inference. Zero/constant, nonfinite or sample-std <=1e-6 windows are invalid. Preserve float64 input for large-offset ADC counts; calibrated metre-scale displacement is a separate CAP input.

If `distance_km/azimuth_deg` are absent, provide event and station `latitude/longitude` in degrees. The program uses spherical source-to-station geometry.

### CAP displacement input

`observations.npz` must contain:

```python
# displacement: ndarray [number_of_stations, number_of_samples, 3]
# Unit: metres; order N, E, Z-up; records aligned to the JSON station list.
np.savez_compressed('observations.npz', waveforms=displacement)
```

- `quantity` must be `displacement_m`: remove the instrument response outside this program. Raw ADC counts are not physical CAP amplitudes.
- `coordinates="NEZ"` means north/east/up; `"NED"` means north/east/down. The internal source convention is NED.
- `dt_s` is the CAP sample interval. CAP records can be sampled more coarsely than the separate 100 Hz raw-Z CNN inputs.
- `t0_s` is the first sample time relative to origin; use a scalar or one value per station. Pre-origin records can have negative `t0_s`.
- `synthetic_samples` must be a power of two >=64. Its default is the next power of two covering the observed sample count. Synthetics begin at origin time zero; choose a duration that covers the required windows.
- A fixed coverage mask excludes incomplete windows. Provide longer correctly aligned records if every segment is excluded.

There is no instrument-response removal or phase-picking engine embedded in this program. Manual picks can override DNN window centering.

## 5. CAP settings and outputs

Defaults in the `cap` object:

| Setting | Default | Description |
|---|---|---|
| `body_band_hz` | `[0.05, 0.5]` | Body-wave passband, below Nyquist |
| `surface_band_hz` | `[0.02, 0.1]` | Surface-wave passband; periods must remain within 2–80 s |
| `window_samples` | `128` | Interpolation samples per segment |
| `body_before_p_s` | `2.0` | Start before first P |
| `body_after_s_s` | `2.0` | Body-window extension after first S, before duration limits |
| `surface_padding_s` | `15.0` | Padding around frequency-dependent group arrivals |
| `body_shift_s` | `2.0` | Absolute Pnl shift bound |
| `surface_shift_s` | `5.0` | Rayleigh/Love shift bound |
| `polarity_weight` | `0.2` | First-motion loss coefficient; `0` disables this term |
| `shift_penalty` | `0.001` | Regularizer on normalized shifts |
| `starts` | `64` | Simultaneous independent mechanism starts |
| `steps` | `1000` | Optimization iterations |

There are five segments: **Pnl D/R, Rayleigh D/R, Love T**. Pnl and Rayleigh each share a shift between their two components; Love has its own shift. Recorded shifts mean `synthetic(t + shift)` is compared with `observed(t)`.

Data and synthetics share a zero-phase FFT filter with Butterworth-shaped amplitude weights and doubled-length zero padding. Distance amplitude weights use exponents 1.13 / 0.74 / 0.55 for Pnl / Rayleigh / Love. Segment duration and taper enter the residual weights. The waveform residual is scaled by **one weighted observed energy**, preserving relative amplitudes across stations, components and wave groups. Individual channel gains are not fitted.

The source is a dimensionless half-cosine-rise moment history of duration `source_duration_s`, saturating at one. GRTM convolves its impulse kernels with that history, including `dt`, to produce displacement in metres. `M0 = 10**(1.5*Mw + 9.1)` in N m.

| Output file | Contents |
|---|---|
| `result.json` | Best mechanism, equivalent nodal planes, moment tensor, Mw/depth where applicable, station diagnostics, shifts and losses |
| `all_depth_results.json` | Every physical depth-grid candidate |
| `mechanism.png/.pdf` | Equal-area lower-hemisphere focal sphere and first motions |
| `waveform_fit.npz` | Observed/predicted segment arrays, sample times and coverage masks |
| `waveform_fit.png/.pdf` | Five-segment waveform comparison; display scaling is shared per station |

Moment components are `(NN, EE, DD, NE, ND, ED)`. Polarity-only tensors have unit scalar moment and no estimated magnitude. Joint tensors are in N m. Positive P radiation corresponds to U. Probability scores are used continuously with confidence weighting, not interpreted as calibrated correctness percentages.

## 6. DNN phases, gradients and physical scope

| Family | Definition / scope |
|---|---|
| `P_first` | Existing first-P network; earliest among its trained P/p/Pn branches |
| `S_first` | New network trained on earliest S/s/Sn |
| `P, p, Pn, Pg, S, s, Sn, Sg, pP, sP, PP, SS` | Earliest returned ray within each named phase |
| `Pg_regional` | Earlier valid p/Pg branch for a crustal source |
| `Sg_regional` | Earlier valid s/Sg branch for a crustal source |
| `rayleigh, love` | Fundamental-mode phase/group velocities and group arrivals, periods 2–80 s |

Regional catalog Pg/Sg may include the upgoing direct p/s branch; they are not identical to literal TauP Pg/Sg names. The supplied CSNDATA workflow uses explicit regional aliases. First-motion constraints accept only direct P-family phases (`P_first`, `Pg_regional`, `P`, `p`, `Pn`, `Pg`); converted/reflected and S arrivals cannot be inserted into the direct-P radiation likelihood.

Body networks cover **depth 0–200 km, epicentral distance 0–3000 km** for the three fixed Earth models. A shared network was refined into 39 independent Earth/phase experts with travel-time and input-gradient supervision. Missing phases remain invalid/NaN, not imputed zero times. The API returns both arrival validity and gradient validity; interfaces, the coincident origin and uncertain alias switches have additional exclusions. The availability classifier is approximate, and validity is not an error certificate.

For `T(h,d)`, the gradient is `[dT/dh, dT/dd]` in s/km. Takeoff is

```text
theta = atan2(abs(dT/dd) * R/(R-h), -dT/dh)
R = 6371 km; theta: 0° down, 90° horizontal, 180° up
```

Surface group arrival time is `distance / U(period)`. CAP windows span group arrivals across the passband; no constant universal surface-wave speed is assumed. Higher modes and arbitrary new velocity models have not been trained.

The regional GRTM stack is a flat-layer approximation of each named radial model to 410 km depth, with a half-space below, Qp=1000 and Qs=600. **CAP Green synthesis is limited here to positive distances <=500 km**, with a recommended regional range of 10–500 km. This is not a locally calibrated crustal model.

### Python API and gradient use

```python
import torch
from seismic_joint.travel import NeuralTravelTimes
from seismic_joint.api import predict_first_motion, window_raw_z, invert_event

travel = NeuralTravelTimes(device='cuda:0', earth_model='iasp91')
h = torch.tensor([10.0], device='cuda:0', requires_grad=True)
d = torch.tensor([100.0], device='cuda:0', requires_grad=True)
r = travel.body_arrival(h, d, phase='Pg_regional', create_graph=True)
print(r['time'], r['gradient'], r['takeoff_angle'], r['gradient_valid'])
if bool(r['gradient_valid'].all()):
    dh, dd = torch.autograd.grad(r['takeoff_angle'].sum(), (h, d))

# A raw window tensor [batch,1024]; preserve the probability path for gradients.
raw_z = torch.randn(1, 1024, dtype=torch.float64, device='cuda:0', requires_grad=True)
first_motion = predict_first_motion(raw_z)
# first_motion: probabilities[:,0]=U, probabilities[:,1]=D; direction 0/1/-1;
# valid=False and zero probabilities mark invalid waveforms.

result = invert_event('examples/synthetic/event.json', 'results/python_demo',
                      mode='joint', device='cuda:0')
```

`create_graph=True` retains the second derivatives of time needed to differentiate an angle-dependent loss. `window_raw_z()` supports piecewise-linear arrival-time derivatives. The event reader treats observed polarity inputs as fixed during mechanism fitting.

`GRTMGreens.differentiable_forward()` exposes native first-order layer/MT derivatives at fixed source/receiver geometry. Mechanism fitting uses the exactly linear six-component physical Green bank. **Native GRTM does not supply an exact source-depth geometry derivative through this interface**: default source-depth estimation uses a physical outer depth grid with fixed observed windows/weights. `interpolate_depth()` supplies an optional, approximate piecewise-linear bank derivative; it is not claimed as an exact native depth derivative. This is not a joint structural inversion workflow with a continuously parameterized DNN Earth model.

## 7. Accuracy, reproduction and troubleshooting

See [the full validation report](docs/VALIDATION.md), [phase error CSV](verification/body_phase_accuracy.csv), and [gradient evidence](verification/joint_gradient_validation.json). Independent holdouts retain tail errors and branch-switch cases. Some p/s and reflected/multipath phases retain large time/angle tails; mean error alone cannot justify a full high-accuracy TauP replacement.

```bash
python -m unittest discover -s tests -v
python scripts/verify_assets.py
# CUDA numerical audits:
python scripts/validate_pipeline.py
python scripts/validate_joint_gradients.py
python scripts/verify_green_quadrature.py
```

The reproduction scripts use the recorded `cuda:0/cuda:1` assignments; edit their device settings if your machine has fewer GPUs. Recorded JSON evidence is provided for inspection without rerunning the physical solve.

Offline retraining, on the remote compute host:

```bash
# Offline teacher environment requires ObsPy; normal inference does not.
python scripts/prepare_earth_models.py
python scripts/generate_body_labels.py --workers 24
python scripts/train_body.py --device cuda:0
python scripts/refine_body_experts.py --device cuda:1
python scripts/train_surface.py --device cuda:1
```

Run the body stages in order. `data/` is generated locally and is not tracked. `train_surface.py` reuses labels if `data/surface.npz` exists. Existing first-P and polarity weights are reused, not retrained by these scripts. The CNN was trained on 2009–2019 CSNDATA with 2020–2022 tests; these year splits do not describe the independently generated Earth-model travel-time labels.

| Problem | Check |
|---|---|
| Missing `SurfaceWave` or preview options | Install the matching GRTM dev12 wheel, rather than stable 0.5.x |
| Missing checkpoint / checksum failure | Complete the clone, keep `assets/`, run `scripts/verify_assets.py` |
| No reliable P/S or invalid angle | Inspect phase definitions, domain, interfaces and validity; do not substitute zero angles |
| No complete CAP windows | Check origin-relative `t0_s`, `dt_s`, synthetic duration, passbands and record coverage |
| Raw Z rejected | Check 100 Hz, 1024 samples or continuous-trace context, finite values and raw amplitude scale |
| Poor amplitude fit | Check displacement units, instrument-response removal, component directions, source duration and velocity model |
| CUDA out of memory | Reduce `cap.starts` and window count; keep a physically adequate synthetic duration |
| Different mechanism angles | Compare both nodal planes or normalized tensors before assuming disagreement |
